# 骑行轨迹地图

把华为运动健康导出的骑行记录，画在一张地图上。

### 👉 在线体验：https://tixi103.github.io/cycling-track-map/

打开就能用，不用安装任何东西。导进去的轨迹只存在**你自己浏览器**里，不上传任何服务器 —— 每个人看到的都是各自的数据。

也可以把整个项目下载下来，双击 `index.html` 运行（效果完全一样，只是离线可用）。

---

## 快速开始

**1. 从手机导出骑行记录**

华为运动健康 → 运动记录 → 点开一条记录 → 轨迹 → 右上角菜单 → **导出路线文件**（选 GPX 格式）→ 传到电脑。

**2. 打开工具**

双击 `index.html`。推荐用 Chrome 或 Edge。

**3. 把文件拖进去**

拖进页面左上角的虚线框即可。支持一次拖多个，也支持整个文件夹。

## 功能

| | |
|---|---|
| **三种格式** | `.gpx` / `.tcx` / `.kml`，自动识别，不看扩展名看文件内容 |
| **多轨迹叠加** | 一次导入几十上百条，按时间渐变 / 单色 / 分类三种方式着色 |
| **地图底图** | 高德路网、高德影像、OSM 标准图、OSM 人道主义图、空白底图 |
| **坐标纠偏** | 高德底图自动做 WGS-84 → GCJ-02 转换，轨迹严丝合缝压在马路上 |
| **统计分析** | 里程、爬升、用时、均速、极速，全部合计或单条查看 |
| **速度剖面** | 沿里程展开的速度曲线，悬停时地图上有游标联动 |
| **轨迹回放** | 按真实时间戳插值播放，可拖进度条、可调 1×～64× 倍速 |
| **按速度着色** | 单条轨迹按快慢染色（浅=慢，深=快） |
| **热力图** | 所有轨迹叠成密度图，一眼看出骑得最多的路 |
| **数据管理** | 显隐、改名、删除、导出/导入备份 |

## 为什么值得一看

**它是拿真实数据验证过的，不是「跑通了就算」。**

用 46 个真实的华为导出文件（44 GPX + 1 TCX + 1 KML，合计 744 公里）做了交叉验证：

**同一趟骑行的三种格式，解析出来完全一致：**

```
GPX  点 4000  里程 33.686km  用时 2:15:17  首点 33.067331,107.044987
TCX  点 4000  里程 33.686km  用时 2:15:17  首点 33.067331,107.044987
KML  点 4000  里程 33.686km  用时 2:15:17  首点 33.067331,107.044987
```

**里程与用时与华为 App 精确相等** —— 设备把汇总数据写在文件里了，程序优先采用它，而不是自己反推一个近似值。

自动化测试共 **162 项断言**（`node dev/run-tests.js`），覆盖解析、渲染、坐标纠偏、文件选择、导入导出，以及上面这组真实数据交叉验证。

### 开发过程中被真实数据打脸的几处

仿真样本只能证明「代码按我设想的格式工作」，证明不了「我设想的格式是对的」。真实文件一进来就发现：

- 真实格式是 `creator="Health"` + **GPX 1.0**，不是常见的 `"HUAWEI Health"` + 1.1
- `<trkpt>` 里**只有经纬度和时间**，没有海拔、心率、速度
- 华为的 KML 把**每个轨迹点写成一个独立 Placemark**，而不是 `LineString`
- 「骑行用时」不能自己算 —— 实测最大偏差 **−37%**，因为设备的暂停判定来自它自己的传感器，从导出的点里推不出来
- 最高速度会显示 94.7 km/h 这种荒谬值 —— GPS 冷启动时头几个定位点能跳到十几米外

## 技术说明

**零构建**：没有 npm、没有打包器、没有 TypeScript。传统 `<script>` 标签 + `window` 全局变量，改完存盘刷新即可。

**能双击运行**：全部资源本地化（Leaflet 1.9.4 已内嵌），不依赖任何 CDN。因此不能用 ES module、不能用 Web Worker —— 这些在 `file://` 下会被浏览器拦掉。

```
index.html
css/app.css
js/
  xmlutil.js     命名空间无关的 XML 读取
  geo.js         距离、抽稀、统计、速度跳点过滤
  coord.js       WGS-84 ⇄ GCJ-02 坐标纠偏
  parsers.js     GPX / TCX / KML 解析
  store.js       本地持久化（IndexedDB → localStorage → 内存，逐级降级）
  basemaps.js    底图注册表
  mapview.js     地图渲染层（唯一直接操作 Leaflet 的地方）
  tracks.js      轨迹状态与配色（唯一持有数据的地方）
  ui.js          列表、统计、提示、上传
  format.js      单位/时间格式化
  profile.js     速度剖面图
  replay.js      轨迹回放
  app.js         主控与事件接线
dev/             开发与测试工具（部署时可整个删掉）
```

### 跑测试

```bash
node dev/run-tests.js
```

四组测试，共 162 项断言，全部通过退出码为 0：

```
解析层自检 …          passed=69
端到端测试 …          passed=61
真实文件交叉验证 …    passed=23
文件选择控件 …        passed=9
```

测试全程用 CDP 在**真实时间**下驱动浏览器。
（踩过的坑：无头浏览器的 `--virtual-time-budget` 会让时钟变成虚拟的，
凡是异步 + 真实 I/O 的行为 —— IndexedDB、文件读取、瓦片加载 ——
用它测会得到**完全相反**的结论。详见 `dev/cdp.js` 顶部注释。）

## 数据存在哪

**只存在你自己电脑的浏览器里**，不上传任何服务器，断网也能看。

换电脑或换浏览器就看不到了，所以骑了新路线之后建议点一次「导出备份」，
会得到一个 `.json` 文件，换设备时导入即可还原。

> **Firefox 用户注意**：Firefox 从 68 版起把每个本地文件当成独立来源，
> `file://` 下不让用 IndexedDB，也就是**存不住数据**（页面会明确提示）。
> 用目录里的 `启动本地服务器.bat` 通过 http 打开即可解决（需要 Python）。

## 部署

本项目已经部署在 GitHub Pages 上：**https://tixi103.github.io/cycling-track-map/**

想部署自己的一份也很简单 —— 这是个纯静态页面，不需要任何后端：

1. Fork 或克隆这个仓库
2. 仓库 → Settings → Pages → Source 选 `main` 分支、目录选 `/ (root)`，保存
3. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`

每个访客看到的都是自己浏览器里存的轨迹，不会互相干扰 —— 这个工具压根没有后端。

详细的图文说明见 [使用说明.md](使用说明.md)。
